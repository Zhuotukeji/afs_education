# AFS 职业教育内容站 PRD v1.1

> 产品代号：Career Path Brief（暂定）
> 文档状态：v1.1，可进入设计、开发与内容生产
> 初版日期：2026-07-24
> 本次修订：2026-07-28（扩展内容体系、去 AI 味机制与视觉设计规范）
> 默认市场：美国、英语内容、移动端优先
> 产品类型：职业路径与短期培训/证书决策内容站
> 商业化方式：站内搜索 AFS + 合规内容页 Related Search for Content（审批通过后启用）

## 0. 结论与关键决策

本站不做招聘站、学校黄页或只有搜索框的广告承载页，而是做一个可在没有广告的情况下独立使用的职业决策产品，核心命题为：

**帮助没有四年制学位、正在转行或希望提升技能的美国成年人，弄清某个职业是否适合自己、入行需要什么、培训要多久、证书是否必要，以及下一步应该做什么。**

首发聚焦三类职业：医疗支持、技术工种、商业与 IT 支持。内容以美国劳工统计局、O*NET、CareerOneStop、州级监管机构和证书颁发机构等一手来源为依据。

本 PRD 采用三个规则等级：

- `P0 政策硬要求`：违反可能造成不批准、限流、停用广告或账号风险。
- `P1 内部提审门槛`：Google 未规定具体数量，但为了证明站点具有独立价值，提审前必须达到。
- `P2 上线优化项`：不阻塞首发，可在站点稳定后迭代。

不能承诺 100% 通过审核。目标是把可控项做到可审计、可复核，并显著降低“低价值内容、站点不完整、误导体验、无效流量和广告实施违规”的风险。

## 1. 背景

账号已具备 AFS 权限，但新域名仍需在 AdSense 的“网站/Sites”中完成站点级审核。附件指南强调：高质量站点应具备相关性、深度、原创性、清晰结构和准确性；自 2024-03-04 起，新 AFS 站点需要站点级批准；内容相关搜索不能放在无内容、广告多于内容、直接复制或具有欺骗性的页面上。

因此，本项目的第一目标不是迅速堆出大量关键词页，而是建立清晰的受众、稳定的编辑标准、真实作者责任、可工作的站内搜索，以及持续更新的内容资产。

## 2. 产品目标与成功标准

### 2.1 业务目标

1. 建立一个能够长期更新、自然获得搜索和直接访问流量的职业教育内容品牌。
2. 通过 AdSense 站点级审核，站点状态达到 `Ready`，且政策中心无未解决问题。
3. 在不牺牲用户体验的前提下，通过真实站内搜索需求获得 AFS 收益。
4. 审批后逐步验证 Related Search 和付费流量，形成可追踪、可停用的实验流程。

### 2.2 用户目标

用户完成一次访问后，应至少能回答以下三个问题：

- 这个职业实际做什么，适不适合我？
- 入行必须满足哪些教育、证书或州级许可要求？
- 我下一步应该查什么、准备什么或比较什么？

### 2.3 提审成功标准

`P0`：

- 域名所有权验证完成，HTTPS 正常，AdSense 中站点状态可提交审核。
- 同一合作方只使用现有的一个 AFS Online 账号，不为新站重复创建账号。
- 无占位内容、断链导航、伪造作者、盗版素材、误导按钮或鼓励广告点击的文字。
- 隐私政策、Cookie 说明、服务条款、联系我们、关于我们、编辑政策和更正政策均可访问。
- AFS 与 Related Search 的实现符合 Google 当前官方政策。
- 如接收 EEA/UK 流量，广告请求前启用 Google 认可的 CMP/TCF 同意流程。

`P1`：

- 至少 125 个可索引的实质内容页面，不含标签页、搜索结果页和法律页；其中至少包含 8 篇真实采访/从业者故事、4 篇原创数据解读和 4 个可用工具。
- 100% 内容页面具有作者、审核者或编辑责任人、发布日期、最近更新时间和来源清单。
- 所有可核实数字和监管性结论均有一手来源；抽检准确率 100%。
- 任何内容类型都不得通过增加数量抵消质量缺陷；若团队无法达到采访、数据和事实核验配额，应延后提审。
- 移动端主要路径无严重可用性问题，站点搜索、筛选、工具和联系表单均可工作。
- 连续 14 天无大规模 404/5xx、索引阻断、恶意流量或异常访问峰值后再提审。

> “60 页”和“14 天”是本项目的内部质量门槛，不是 Google 公布的固定审批条件。

## 3. 目标用户

### 3.1 核心用户

- 18-44 岁，希望在 3-24 个月内进入新职业的成年人。
- 没有四年制学位，或不希望再次完成完整学位的人。
- 正在比较职业培训、行业证书、学徒制和社区学院路径的人。
- 需要理解不同州许可要求、培训周期、费用和工作环境的人。

### 3.2 典型任务

- “成为 HVAC technician 需要多长时间？”
- “Medical assistant 和 dental assistant 哪个更适合我？”
- “Pharmacy technician 在 Texas 是否需要执照？”
- “CompTIA A+ 对 help desk 工作是否必要？”
- “如何判断一个短期培训项目是否值得报名？”

### 3.3 非目标用户

- 寻找即时职位投递或雇主联系方式的人。
- 需要个性化法律、医疗、移民或金融建议的人。
- 寻找“保证就业”“保证高薪”“免费补贴”或贷款审批的人。

## 4. 产品定位与边界

### 4.1 核心价值

- 将分散在政府、州级监管机构和证书机构的信息整理成可执行的职业路径。
- 清楚区分“法律强制许可”“雇主偏好证书”“可选培训”和“营销性证书”。
- 同时呈现优势、代价、限制和不适合人群，避免只写正面宣传。
- 提供比较工具和检查清单，让用户不依赖广告也能完成决策。

### 4.2 首发不做

- 不做职位聚合、伪招聘、简历收集或雇主线索转卖。
- 不做学校排名、付费榜单、未经验证的学生评价或“最佳学校”列表。
- 不做贷款、奖学金匹配、补贴领取或“零成本培训”承诺。
- 不自动生成 50 州、城市、“near me”或长尾关键词页面。
- 不上线开放投稿、论坛、评论区和用户生成内容。
- 不做与页面内容无关的下载按钮、系统提醒或假消息通知。

### 4.3 后续可评估

- 经人工审核的培训项目目录。
- 非付费的官方项目数据库接入。
- 收藏、比较列表和邮件更新。
- 经过明确披露的联盟合作，但不得影响编辑结论。

## 6. 页面需求

### 6.1 首页

目标：在首屏和一次滚动内说明品牌、受众和站点能解决的问题。

必须包含：

- 品牌名称和一句清晰定位，不使用“全网最权威”“保证就业”等不可证明表述。
- 可用的站内搜索框，placeholder 示例仅说明输入内容，不预填查询。
- 三个职业领域入口。
- 6-9 个精选职业指南，明确显示最近更新日期。
- 一篇真实从业者故事和一个原创数据模块，展示站点不是模板文章集合。
- “如何研究内容”的简短入口，链接至编辑政策。
- 工具入口和最新更新内容。
- 完整页脚和法律/联系页面链接。

验收：关闭广告脚本后，首页功能和信息仍完整；不得以 AFS 单元作为首页主体。

### 6.2 栏目中心页

目标：帮助用户理解一个职业领域并进入具体指南，而不是只有文章卡片列表。

必须包含：

- 400-800 词的原创领域概述。
- 职业类型、常见入行路径、典型监管差异和比较维度。
- 人工策划的职业列表和推荐阅读顺序。
- 内容负责人与更新时间。

禁止：只有标题链接、自动摘要或分页列表的薄栏目页。

### 6.3 职业路径页

每页围绕一个真实职业，回答完整决策链。推荐结构：

1. 一句话结论与适合/不适合人群。
2. 日常职责和真实工作环境。
3. 最常见的入行路径，区分“必须”和“通常偏好”。
4. 教育与培训周期。
5. 证书、注册和州许可要求。
6. 培训费用范围及其口径，不提供贷款建议。
7. 工资与就业前景，说明年份、地区差异和数据来源。
8. 进入该职业的分步清单。
9. 常见误区、风险和替代职业。
10. 一手来源、作者、事实审核者和更新记录。

验收：典型篇幅 1,200-2,200 英文词，但以回答完整性而非字数为准；至少引用 2 个一手来源；不得将全国数据伪装成本地保证薪资。

### 6.4 证书/许可指南页

必须明确：

- 颁发机构及其官方链接。
- 它是法律要求、雇主偏好还是可选项。
- 报考资格、考试形式、公开费用、有效期和续证要求。
- 适用与不适用人群。
- 与同类证书的差异。
- 信息核验日期。

禁止仿冒颁发机构、使用易混淆域名或把第三方培训证书写成政府许可。

### 6.5 比较页

比较维度至少包括：职责、工作环境、入行时间、教育要求、许可、成本、工资数据、就业前景、体力/排班要求和适合人群。

比较结论不能由单一工资数字决定；表格之后必须有人工解释和选择建议。禁止批量替换职业名称生成近似页面。

### 6.6 州级要求页

只在州规则确有差异且完成一手核验后发布。每页必须包含：

- 主管机构、法律/规则页面和核验日期。
- 注册、许可或背景审查流程。
- 续期、继续教育和跨州互认信息（如适用）。
- “本页为一般教育信息，不构成法律建议”的说明。
- 至少 300 词的该州独有解释，不计通用模板文字。

禁止首发 50 州全覆盖；禁止只有州名不同的程序化页面。

### 6.7 工具页

首发四个工具：

1. `Training Cost Planner`：输入学费、材料、考试、通勤和停工时间，输出总成本区间。
2. `Career Comparison Worksheet`：选择两个职业，对照已核验的路径、要求和工作环境。
3. `Program Evaluation Checklist`：根据认证、费用透明度、完成率披露、退款规则和就业宣传生成检查清单。
4. `State Requirement Navigator`：按职业和州查找已人工核验的主管机构、许可状态和官方下一步，不自动生成未核验页面。

工具必须公开公式、数据来源和局限；结果不能声称保证回报、录取或就业。页面需有足够说明内容，不能只有输入框和广告。

### 6.8 技能提升与职业发展页

围绕“入行以后如何继续发展”提供独立内容，包括入门技能清单、常见晋升路径、证书续期、继续教育、从相邻岗位转入和何时不值得继续投入某项证书。

每页必须以具体职业或证书为范围，不发布“成功人士的十个习惯”一类泛化内容；应包含技能来源、实际工作任务映射和可执行的 30/60/90 天学习计划。

### 6.9 真实从业者故事与专家问答页

目标：引入真实经验、语气和细节，建立站点的编辑部特征。

必须满足：

- 采访对象身份经核验并书面同意发布；允许因隐私隐藏姓氏或雇主，但编辑部保留核验记录。
- 保存录音、文字稿或完整采访笔记；直接引语不得由 AI 补写或润色到改变原意。
- 清楚区分个人经验和普遍事实；工资、许可等结论仍需独立来源。
- 同时询问困难、误区、后悔点和不适合人群，不做只有正面反馈的宣传稿。
- 若采访对象或机构提供报酬、样品或商业关系，必须披露；首发不接受付费采访。

每篇建议包含“进入这个职业前最希望知道的事”“真实的一周”“最难的环节”“给新人的一条建议”和编辑核验注释。

### 6.10 原创数据解读页

使用 BLS、O*NET、CareerOneStop 和州级公开数据回答明确问题，例如“哪些短期培训职业的排班更稳定”或“证书要求与工资中位数是否同步变化”。

必须包含研究问题、数据版本、筛选条件、计算方法、局限、可下载数据表或明细，以及至少一张原创图表。禁止通过选择性展示数据制造“最高薪”“最容易”之类夸张结论。

### 6.11 作者与信任页面

- 作者必须是真实存在并同意公开的人，不使用 AI 生成头像、虚构经历或虚假资格。
- 作者页展示相关经验、负责主题、审核机制和全部文章。
- 关于我们说明站点所有者、编辑使命、联系方式和商业模式。
- 编辑政策说明选题、引用、AI 辅助、事实核查、利益冲突和更新流程。
- 更正政策提供可用邮箱/表单，并说明更正记录如何展示。
- 广告披露明确广告不等于编辑推荐。

## 7. 站内搜索与 AFS 需求

### 7.1 站内搜索基础功能

- 全站页头提供统一搜索入口。
- 用户主动提交后进入 `/search/?q={query}`。
- 查询长度 2-80 字符；转义 HTML；过滤脚本、控制字符和明显机器人请求。
- 搜索结果由站内内容索引提供，展示标题、摘要、内容类型和更新时间。
- 结果按相关性排序，可按职业领域和内容类型筛选。
- 搜索页使用 `noindex,follow`，不进入 XML sitemap。
- 空查询、非法查询和零结果页不显示 AFS 广告；提供栏目和热门指南作为退出路径。
- 即使 AFS 加载失败，站内结果仍可正常使用。

### 7.2 AFS 搜索广告实施

`P0`：

- 仅在用户主动产生的有效搜索结果页加载 AFS 搜索广告。
- 使用 AdSense 后台生成的搜索样式和官方代码，不修改广告 iframe、点击区域、标签或广告响应。
- 广告与普通站内结果在视觉上可区分，不伪装成导航、下载或系统消息。
- 不预填、自动提交、静默改写或循环刷新查询。
- 不用弹窗、遮罩、强制滚动或页面跳转诱导用户接触广告。
- 不出现“支持本站请点击广告”等鼓励点击文字。
- 广告脚本故障时页面不得白屏、跳转或失去主要内容。

内部首发规则：每个搜索页只使用一个 AFS 主单元；广告位置和数量后续仅通过正式实验调整。

技术上必须提供独立功能开关：`afs_search_enabled`、`rsoc_enabled`、内容 ID 允许清单和流量来源允许清单。合规负责人应能在不重新部署网站的情况下全站停用任一广告能力；预发布环境使用独立测试配置，不得产生正式流量或正式广告点击。

### 7.3 Related Search for Content 实施

Related Search 只允许出现在已通过内容质量检查的职业、证书、比较和州级指南页。

首发规则：

- 每页最多一个 Related Search 单元。
- 放在用户已读到核心答案之后，例如正文 35%-60% 处或结论之后；不得成为首屏主体。
- 不在首页、栏目列表、搜索页、工具结果页、法律页、联系页、404、空内容页和未完成页面展示。
- 页面正文必须明显多于广告和付费推广内容。
- 不修改 Google 返回的词语、布局含义或点击行为。
- 关闭该单元后，页面仍应完成原本的用户任务。

若流量来自受控的付费广告或外部受控链接：

- Related Search 请求必须按 Google 要求通过 `referrerAdCreative` 原样传入广告创意文字。
- 视频创意保存并传入准确的音频文字稿。
- 创意文案、落地页标题和正文承诺保持一致，不使用点击诱饵或落地页无法兑现的表述。
- 每个创意 ID 必须可追溯到素材、文字稿、投放平台、落地页和上线时间。

## 8. 首发内容计划

### 8.1 内容库存

### 8.3 内容差异化要求

每篇内容至少提供三项非简单改写的附加价值，其中至少一项必须来自“本页专属研究”或“真实人工采集”：

- 对官方规则的通俗解释。
- “必须/偏好/可选”三层判断。
- 多来源冲突或口径差异说明。
- 工作环境、排班和体力要求等决策信息。
- 可打印检查清单或真实计算工具。
- 相邻职业的退出/替代路径。
- 明确的更新时间和变更记录。
- 原创图表、流程图、决策树或计算结果。
- 经过核验的从业者引语、专家解释或编辑现场笔记。

以下内容不计入 125 页库存：单独标签页、站内搜索结果、自动聚合页、只有定义的术语页、只有一张图表的页面、未完成州页面、转载或简单改写页面。

### 8.4 固定编辑栏目

为形成连续运营感，首页和栏目页使用固定栏目，而不是每天随机发布关键词文章：

- `Credential Decoder`：每两周拆解一个证书，明确“必须/偏好/可选”和隐性成本。
- `Work Reality`：每月两篇真实从业者访谈，重点写排班、体力要求、压力来源和离职原因。
- `State Rule Watch`：每月汇总已核验的州级许可变化，旧文同步更新并保留变更记录。
- `Training Cost Desk`：每月选择一个培训路径，公开费用构成和容易遗漏的支出。
- `Route Map`：用时间线展示从零经验到可申请岗位的多个可选路径。
- `What We Updated`：每月公开主要更正、数据更新和新增来源，强化编辑透明度。

每个固定栏目拥有负责人、发布节奏和归档页。连续两个月无法按节奏产出时，应缩减栏目数量，不发布空壳栏目。

### 8.5 内容质量评分

每个页面发布前按 100 分制评分，低于 85 分不得发布；“事实准确性”或“原创价值”任一项低于最低线时，即使总分达标也不得发布。

| 维度 | 分值 | 最低线 | 判断标准 |
|---|---:|---:|---|
| 事实准确性与来源 | 25 | 23 | 关键结论可追溯、口径和日期明确 |
| 决策完整性 | 20 | 16 | 能回答适合谁、代价、要求和下一步 |
| 原创价值 | 20 | 16 | 有本页专属研究、采访、工具或图表 |
| 人工编辑特征 | 15 | 12 | 有明确判断、细节、限制和真实语气 |
| 可操作性 | 10 | 8 | 用户能据此执行检查、比较或规划 |
| 阅读与视觉呈现 | 10 | 8 | 结构清楚、移动端可读、图表准确 |

## 9. 编辑与事实核查流程

### 9.1 来源优先级

1. 联邦和州政府、监管机构、法律法规原文。
2. BLS Occupational Outlook Handbook、O*NET、CareerOneStop、College Scorecard。
3. 证书颁发机构和认可机构的官方资料。
4. 经认可学校的项目资料，仅用于举例，不据此做全行业结论。
5. 高质量行业协会或研究报告。

商业博客、搜索结果摘要和 AI 输出不得作为事实结论的唯一来源。

### 9.2 内容工作流

`Research brief -> Outline -> Draft -> Source check -> Subject review -> Copy edit -> QA -> Publish -> Scheduled review`

每篇内容在 CMS 中保存：

- 目标用户问题和搜索意图。
- 关键结论及对应来源。
- 数据年份、访问日期和适用地区。
- 作者、事实审核者和发布批准人。
- 下一次复核日期。
- 重大修改记录。

### 9.3 AI 使用规则

“去 AI 味”不是规避检测器，而是让内容真正包含机器无法凭空拥有的采访、取舍、核验过程和编辑判断。允许 AI 辅助整理资料、生成初步提纲、检查可读性和发现遗漏，但不能替代调查、写作责任或最终表达。

#### 9.3.1 每篇必需的人工作业

普通指南至少完成以下四项，旗舰页、访谈和数据页要求更高：

1. 编辑先写一份 150-300 词的 `editor memo`，说明用户真正纠结什么、本页准备给出什么判断、哪些问题仍不确定。AI 不得生成这份 memo。
2. 至少加入一项本页专属证据：人工整理的数据、官方规则对照、真实采访、课程样本核验、费用拆解或实际工具结果。
3. 作者明确写出一个不直观发现、一个限制条件和一个不适合该路径的人群。
4. 审核者打开原始来源逐项核对，不只检查引用链接是否存在。

职业路径页每 4 篇至少有 1 篇获得从业者或领域专家输入；没有直接采访的页面应链接到同职业领域的真实故事，并说明个体经验不能代表全部从业者。

#### 9.3.2 英文写作风格

- 开头 120 词内进入具体决策、任务或代价，不从行业宏大背景写起。
- 优先写具体名词、动作、数字口径和场景，减少 `can help`、`may want to consider`、`various factors` 等无信息表达。
- 允许明确但有依据的编辑判断，例如“对多数无相关经验者，这张证书不是第一笔该花的钱”，随后给出条件和来源。
- 同时呈现优点、代价、例外和未知项，不以泛化的鼓励性结尾收束所有文章。
- 段落长短和句式自然变化，但不为“像人”故意加入错别字、俚语或虚假第一人称经历。
- 采访对象的原话保留个人语气，只做清晰度和长度编辑；任何实质改写需对方确认。
- 标题与小标题按页面问题定制。职业页可以共享必备信息字段，但不得机械复用完全相同的可见标题顺序。

以下英文表达进入编辑器提示词库，出现时要求作者改为具体信息，而不是机械一键替换：

- `In today's fast-paced/evolving world`
- `Whether you're just starting out or...`
- `It's important to note that...`
- `There are several factors to consider`
- `Embarking on a rewarding career`
- `Navigating the ever-changing landscape`
- `Ultimately, the choice depends on your goals`
- `By understanding X, you can make an informed decision`

#### 9.3.3 四轮人工编辑

1. `Evidence edit`：逐项验证事实、数字、法规、引语和链接。
2. `Point-of-view edit`：检查文章是否真正回答问题，是否敢于说明“不值得”“不适合”或“目前无法确认”。
3. `Language edit`：删除空泛开场、重复总结、对称排比、连续三段相同句式和无意义过渡词。
4. `Read-aloud and cross-page edit`：朗读全文，并与同栏目最近 5 篇比较标题结构、开头、结尾和常用措辞。

机器检查只用于发现风险：

- 非引用正文与站内其他页面出现超过 20% 连续重复文本时，强制人工复审。
- 同模板页面的小标题顺序高度一致或语义近似时，强制重做文章结构。
- 引用 URL 不可访问、数据年份缺失、断言没有来源时，阻止发布。
- AI 检测器结果不得作为发布、拒稿或“内容是人工原创”的证据，因为其误报和漏报均不可控。

#### 9.3.4 明确禁止

- 未经人工逐项核验直接发布 AI 草稿。
- 使用 AI 虚构作者、采访、引用、费用、法规或数据。
- 批量替换职业、州名生成页面。
- 对外声称 AI 是持证专家或实际编辑。
- 为躲避检测而故意改错语法、插入随机词、使用内容混淆工具或伪造“个人体验”。
- 把搜索结果摘要、竞争网站或 AI 生成的二手结论包装成原创研究。

最终内容责任必须落到真实编辑人员。每篇文章在 CMS 中显示“Written by”“Reviewed by”和方法说明；不需要用营销式文字反复强调“100% human-written”。

### 9.4 更新频率

- 州许可、证书考试和费用：每 6 个月复核，发生政策变化时立即更新。
- BLS 工资和就业前景：数据源年度更新后 30 天内复核。
- 培训选择与比较内容：每 12 个月复核。
- 外链：每月自动检测，失效后一周内处理。
- 用户更正：2 个工作日内确认，5 个工作日内完成核验或给出处理状态。

## 10. 视觉与用户体验

### 10.1 设计概念

设计方向为 **Modern field guide + career decision workspace**：兼具编辑出版物的可信度、工具产品的清晰度和真实工作现场的质感。

- 安静、可信、信息密度适中，避免像贷款、招聘、下载或广告套利落地页。
- 品质感来自排版、真实素材、数据可视化和细节一致性，不依靠大面积渐变、发光球体、夸张阴影或满屏卡片。
- 品牌和实际功能必须同时出现在第一视口：用户立即看到站点名称、搜索框和职业领域入口，而不是先读营销文案。
- 页面分区使用全宽色带或留白组织，卡片只用于重复职业项目、访谈和真正需要边界的工具组件；禁止卡片套卡片。

### 10.2 色彩与字体

建议色板：

| Token | 色值 | 用途 |
|---|---|---|
| Ink | `#18201F` | 主文字、深色导航 |
| Evergreen | `#174C43` | 品牌主色、主按钮、重点区域 |
| Paper | `#F7F8F5` | 页面浅背景，不使用偏黄米色 |
| White | `#FFFFFF` | 正文和工具工作区 |
| Signal Coral | `#B3483C` | 小面积强调、关键风险，不作为大背景 |
| Data Blue | `#2F6F9F` | 图表第二序列、信息链接 |
| Line | `#DDE2DF` | 分隔线和边框 |
| Success | `#2B7A55` | 已核验、满足要求 |
| Warning | `#9A6816` | 限制、需要确认 |

所有组合需通过 WCAG 2.2 AA；颜色不能作为“必须/偏好/可选”或图表数据的唯一识别方式。

字体建议：

- 编辑标题：`Source Serif 4`，用于 H1-H3 和数据故事标题。
- 正文与界面：`Inter`，用于正文、导航、按钮和表格。
- 数字与数据注释：`IBM Plex Mono`，仅用于短数字、年份和方法注释。
- 字体加载失败时使用系统 serif/sans 回退；不因字体未加载隐藏文字。
- 字距统一为 `0`，不使用负字距；字号在明确断点切换，不按视口连续缩放。

推荐字号：桌面 H1 `48/56`、H2 `32/40`、H3 `24/32`、编辑正文 `18/30`、UI 正文 `15/22`；移动端 H1 `34/42`、H2 `28/36`、正文保持 `17/28`。

### 10.3 栅格与尺寸

- 全站内容容器最大宽度 `1200px`，桌面边距至少 `24px`，移动端 `16px`。
- 桌面正文页采用 `220px 目录 + minmax(0, 740px) 正文 + 240px 信息栏`；中屏移除右栏，移动端全部单列。
- 正文行长控制在约 65-78 个英文字符。
- 卡片圆角 `6px`，工具输入框和按钮 `4-6px`；只对浮层使用轻阴影。
- 图表、比较表、职业卡和工具输出设置稳定高度/宽高比，加载和交互不得使版面跳动。

### 10.4 首页布局

```text
┌──────────────── Masthead / Search / Navigation ────────────────┐
│ Full-width real workplace image                                │
│ Brand name + literal value statement                           │
│ [ Search careers, credentials, or state requirements ] [Search]│
│ Healthcare Support | Skilled Trades | Business & IT Support    │
└─────────────────────────────────────────────────────────────────┘
  Career Path Explorer - unframed grid, next section visible
  Editor's Desk - one reported story + current credential decoder
  Compare Paths - direct comparison entry
  Data Desk - one original chart with methodology link
  Planning Tools - four compact tool entries
  What We Updated - dated corrections and source updates
```

- 首屏桌面高度控制在 `420-480px`，移动端约 `360-410px`，任何常见视口都应露出下一部分标题或首行内容。
- 背景使用清晰、真实、可识别的工作或培训现场照片；文字直接覆盖在安全留白区域，不放在浮动营销卡片中。
- 照片不得使用黑暗模糊、过度裁切或只表达“氛围”的素材；人物需有授权，工作动作和防护装备要真实。
- 首屏搜索是产品功能，不自动提交或预填查询；搜索按钮使用 Lucide `Search` 图标并有可访问名称。
- 首页各段落交替使用白色、Paper 和深色品牌带，避免整页只有绿色变化。

### 10.5 内容页布局

- 顶部依次为面包屑、内容类型、H1、两句摘要、作者/审核者/更新时间和“数据适用地区”。
- H1 下方先给 `At a glance`：入行时间、典型要求、证书状态、数据年份和主要限制，最多 5 项。
- 桌面左侧目录随阅读高亮；右侧放来源状态、必要定义和工具入口，不放连续广告卡。
- 正文混合使用叙述、证据表、时间线、真实引语、风险提示和原创图表，避免连续十个相同白底模块。
- 关键来源以内联脚注编号和段末来源块呈现；页面底部展示完整来源、方法、变更记录和作者责任。
- Related Search 仅在允许页面、核心答案之后出现，前后至少保留 `32px` 清晰间距，不得与工具或普通相关内容使用同一视觉样式。

### 10.6 比较页与工具页

比较页：

- 桌面双列概览保持列宽稳定；长表第一列固定，移动端允许表格自身横向滚动但页面不得整体横向滚动。
- “更适合谁”使用并列叙述，不用一个总分决定职业好坏。
- 工资、时间和成本图表显示年份、单位、样本/地区和来源。

工具页：

- 桌面采用输入区与结果区并列的工作台，移动端先输入后结果；不把整个工具再包进装饰性大卡片。
- 数值使用输入框、步进器或滑块，模式选择使用分段控件，二元设置使用开关/复选框。
- 按钮使用 Lucide 图标：计算 `Calculator`、重置 `RotateCcw`、下载 `Download`、信息 `Info`；陌生图标提供 tooltip。
- 结果变更使用轻量过渡并保留固定容器高度；支持 `prefers-reduced-motion`。
- 下载或打印内容必须与屏幕结果一致，不使用类似广告的“Download now”按钮文案。

### 10.7 核心组件

- `Requirement status`：Required / Commonly preferred / Optional，使用图标、文字和颜色三重表达。
- `Reality check`：突出排班、体力、压力和常见误区，使用 Signal Coral 细边而非警报式大红底。
- `Route timeline`：展示学徒制、证书、社区学院等并行路线，不暗示只有一条正确道路。
- `Evidence note`：显示来源机构、数据年份、访问日期和解释口径。
- `Field voice`：真实引语、身份核验方式和采访日期。
- `Updated record`：列出内容发生实质变化的日期与原因。
- `Career card`：固定图片比例、职业名、入行时间、许可提示和内容更新时间；整卡可点击时仍提供明确焦点状态。

### 10.8 素材规范

- 首发准备至少 20 张自有或明确授权的真实职业/培训照片，并建立素材台账：来源、许可、人物授权、职业、地点和拍摄日期。
- 同一张主图不得用于两个不同职业；不使用 AI 生成人物冒充真实从业者或培训现场。
- 无法取得真实摄影时，优先使用官方公开数据图、工具截图或编辑部制作的信息图，而不是无关库存照片。
- 原创图表遵循统一图例、单位、来源脚注和色盲友好规则；三维、仪表盘和装饰性图表禁止使用。

### 10.9 交互与可访问性

- 动画时长 `160-220ms`，只用于状态反馈；禁用滚动劫持、自动播放和视差背景。
- 不使用倒计时、伪通知、页面抖动、连续弹窗、全屏插页或难以关闭的横幅。
- 键盘可到达所有控件；焦点环清晰；触控目标至少 `44x44px`。
- 任何 Cookie/CMP 横幅不得遮住隐私选项或制造拒绝困难。
- 广告、站内结果、编辑推荐和外部链接在文字和视觉上都能区分。
- 文本必须在 `360x800`、`390x844`、`768x1024`、`1440x900` 和 `1920x1080` 视口下无重叠、裁切或按钮溢出。
- 除明确的比较表外不得出现页面级横向滚动；超长职业名和机构名必须正常换行。

### 10.10 设计交付与验收

设计阶段必须交付：

- 品牌字标、色彩/排版/间距 tokens 和摄影 brief。
- 首页、职业页、比较页、故事页、数据页、工具页、搜索结果和 404 的桌面/移动稿。
- 导航、搜索、职业卡、证据注释、状态标签、时间线、图表、作者信息和 CMP 的组件状态。
- Loading、empty、error、long text、no image、ad blocked 和 reduced motion 状态。

上线前使用真实英文长标题、长机构名和完整数据测试，不用 Lorem Ipsum。通过桌面/移动截图审查、键盘流程和布局像素检查后才能验收。

## 11. 技术、SEO 与可访问性

### 11.1 技术基线

- HTTPS、稳定托管、自动备份和独立生产/预发布环境。
- 页面采用服务端渲染或静态生成，正文和关键链接无需客户端脚本即可读取。
- 404 返回真实 HTTP 404；重定向不形成链路或循环。
- 生产环境无调试信息、默认后台路径暴露或目录列表。
- 第三方脚本采用允许清单；移除无用途的追踪器。

### 11.2 SEO

- 每个索引页具备唯一 title、H1、meta description 和 canonical。
- XML sitemap 只包含规范、可索引、状态为 Published 的页面。
- `/search/`、预览、筛选参数和内部测试页设为 `noindex`。
- robots.txt 不阻止正常内容和 Google 广告审核所需抓取。
- 使用真实、匹配页面内容的 `Organization`、`WebSite`、`Article`、`Person` 和 `BreadcrumbList` 结构化数据。
- 不滥用 FAQ、Review、JobPosting 或虚假评分结构化数据。
- 图片拥有授权、压缩得当并有准确 alt；装饰图使用空 alt。

### 11.3 性能与质量目标

- 以真实用户数据为准，主要模板达到 Core Web Vitals “Good”目标。
- 移动端首屏不因广告加载产生明显布局偏移。
- 关键页面 JS 错误率低于 0.5%，5xx 低于 0.1%。
- 键盘可完成导航、搜索、筛选和工具操作；焦点状态清晰。

## 12. 隐私、安全与合规

- 只收集完成产品功能所必需的数据；首发不要求注册。
- 搜索查询、分析事件和广告报告中不得传递姓名、邮箱、电话等个人身份信息。
- 联系表单提供用途说明、保留期限和删除流程；启用反垃圾机制但不出售联系人数据。
- 隐私政策披露 Google 等第三方可能使用 Cookie、设备标识和广告数据。
- EEA/UK 流量使用 Google 认可的 CMP；用户同意前不得发送需要同意的广告/分析请求。
- 根据目标地区落实适用的美国州级隐私选择和退出机制。
- 管理后台启用 MFA、最小权限、操作日志和定期权限复核。
- 每季度检查依赖漏洞、第三方脚本和数据保留策略。

## 13. 数据与监控

### 13.1 事件模型

- `search_submit`：查询长度、结果数、来源页面、内容领域；不记录 PII。
- `search_result_click`：结果位置、目标内容 ID、内容类型。
- `filter_apply`：筛选类型和值。
- `tool_start`、`tool_complete`：工具类型和非敏感区间值。
- `source_link_click`：来源机构类型，不把外部 URL 当作用户身份。
- `content_correction_submit`：只记录工单状态，正文与邮箱进入受限系统。

不得通过覆盖层、iframe 监听或其他方式自行截取 AFS 广告点击。广告表现以 AdSense 报告、自定义渠道和允许的官方集成为准。

### 13.2 核心指标

产品质量：

- 搜索成功率（至少一个站内结果）≥ 75%。
- 搜索结果点击率 ≥ 35%。
- 工具完成率 ≥ 45%。
- 来源链接失效率 < 1%。
- 到期未复核内容占比 < 5%。

合规与稳定性：

- 政策中心未解决问题数 = 0。
- 无效流量异常必须在 24 小时内暂停对应来源。
- 创意到落地页映射完整率 = 100%。
- 有资质内容模板的作者/来源/更新时间完整率 = 100%。

商业化指标在审批后观察：搜索量、AFS RPM、CTR、EPC、每会话收益和来源质量。不得单独追求 CTR；任何显著异常先按无效流量处理。

账号级运营还需监控年度 AFS 查询量。附件所列上限为每个账号在 8 月 1 日至次年 7 月 31 日期间 50 亿次查询；实施时以账号最新条款和后台显示为准，并在达到 70%、85%、95% 时分别告警。

## 14. 商业化阶段

财务测算可暂按附件所列 AFS Online 51% 收益分成建立情景模型，但结算、扣减和最终分成必须以账号当前合同及 AdSense 后台为准，不把该比例写入面向用户的宣传内容。

### 阶段 A：内容站建设

- 不投放 AFS、Related Search 或展示广告。
- 完成内容、信任页面、站内搜索、工具和技术 QA。
- 建立 Search Console、分析和错误监控。

### 阶段 B：站点级提审

- 将域名加入 AdSense Sites，按后台提供方式完成所有权/代码验证。
- 发布正确的 `ads.txt`（以 AdSense 后台给出的发布商 ID 为准）。
- 提交审核后冻结大规模模板、域名、导航和内容迁移。
- 每日检查 Sites 状态、政策中心、抓取错误和线上可用性。

### 阶段 C：审核通过后的 AFS 首发

- 仅在有效站内搜索结果页启用一个 AFS 单元。
- 仅在允许清单内容页启用一个 Related Search 单元。
- 创建按模板、领域和流量来源区分的自定义渠道。
- 先使用自然/直接流量建立 2-4 周基线，再做商业化实验。

### 阶段 D：受控付费流量

- 小预算、单平台、单落地页、单创意组启动。
- 启用 `referrerAdCreative`、创意/文字稿归档和自动异常告警。
- 任一来源出现异常 CTR、极短停留、大量重复设备/IP 模式、政策警告或收入扣减时立即停投并调查。

## 15. 付费流量规则

付费流量不是提审前的依赖项，也不应成为站点唯一用户来源。

`P0`：

- 投放平台、素材和落地页必须符合 Google 流量来源与广告实施政策。
- 广告素材不得承诺页面无法提供的职位、薪资、证书、补贴或录取结果。
- 不购买弹窗、强制跳转、工具栏、激励、机器人或来源不透明的流量。
- 不向内容页传递 PII，也不把敏感用户属性编码到 URL。

内部准入门槛：

- 域名已 Ready，政策中心为 0。
- 自然/直接流量下页面和 AFS 行为稳定至少 14 天。
- 已建立创意级追踪、预算上限、异常停投和每日人工复核。
- 首轮仅使用 1-2 个已证明用户任务清晰的落地页。

## 16. CMS 内容模型

每个内容对象至少包含：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| title / slug / summary | 文本 | 是 | 唯一、非关键词堆砌 |
| content_type / topic_cluster | 枚举 | 是 | 职业、证书、比较、州、培训、技能、故事、研究、工具 |
| author_id / reviewer_id | 关联 | 是 | 指向真实作者页 |
| editor_memo | 长文本 | 是 | 用户纠结、编辑判断和未确定问题，不直接前台展示 |
| published_at / updated_at | 日期 | 是 | 前台展示 |
| next_review_at | 日期 | 是 | 到期自动提醒 |
| source_list | 结构化数组 | 是 | 机构、URL、标题、访问日、支持的结论 |
| original_evidence | 结构化对象 | 是 | 采访、数据整理、规则对照、费用拆解或工具结果 |
| interview_record / consent | 受限关联 | 条件必填 | 访谈记录、身份核验和发布授权 |
| methodology / dataset_version | 结构化对象 | 条件必填 | 数据页和计算工具的方法、版本与局限 |

| data_year | 数字 | 条件必填 | 工资、前景等数字口径 |

## 17. 排期与人员

### 17.1 建议团队

- 产品/合规负责人 1 人：范围、政策、提审和风险决策。

- 事实审核 2 人：按领域交叉审核，不能由同篇作者独自完成。
- 数据研究/可视化 1 人：公开数据清洗、方法说明、原创图表和工具数据。
- 设计/前端 1 人、后端/CMS 1 人；小团队可合并。
- 摄影/图片编辑可按项目合作，但素材授权台账由主编负责。

| 第 1-2 周 | 品牌、域名、受众研究、来源台账、编辑手册、摄影 brief、页面原型和采访招募 |

## 19. 主要风险与处理

| 风险 | 早期信号 | 处理 |
|---|---|---|
| 站点被判断为低价值/批量内容 | 页面结构高度重复、来源稀少、无作者责任 | 缩小主题范围，删除薄页，增加一手核验和独有决策信息 |
| 职业内容被误解为招聘或保证就业 | 创意出现“hiring now”“guaranteed job” | 禁用相关词，法务/合规审创意，页面明确非招聘站 |
| 州级页面程序化过度 | 50 州一次上线、正文差异极小 | 首发仅 10 个已核验页面，其余不建 URL |
| 广告多于内容 | 首屏广告密集、正文很短 | 首发每页最多一个 RSOC，内容未达门槛默认关闭 |
| 无效或低质量付费流量 | CTR/会话行为突然异常、收入回撤 | 自动停投、隔离来源、保留日志并复盘 |
| 数据过期 | 证书费用、州规则和工资年份陈旧 | CMS 到期提醒、固定复核周期、更新日志 |
| AI 事实错误或近似重复 | 引用不存在、页面互相矛盾 | 人工事实核验、重复检测、无来源不得发布 |
| 内容有明显 AI 腔调 | 空泛开场、统一句式、每篇相同结尾 | editor memo、专属证据、四轮人工编辑、跨页比较和朗读检查 |
| 采访内容不真实或被过度润色 | 无原始记录、引语像营销稿 | 身份核验、授权与记录归档，实质改写由采访对象确认 |
| 设计精美但像广告落地页 | 首屏大口号、满屏卡片、假按钮 | 首屏提供真实搜索任务，执行第 10 节视觉规范和多视口验收 |
| 素材造成信任或版权风险 | 同一库存图重复、AI 人物冒充从业者 | 使用真实授权素材并维护许可/人物授权台账 |
| 利益冲突影响内容 | 付费项目总是排名靠前 | 编辑与商业隔离、披露、首发不做付费排名 |

## 20. 最终验收定义

产品可提交站点级审核，必须同时满足：

1. 第 18 节全部 `P0` 项通过，`P1` 项无未说明例外。
2. 产品负责人、主编、技术负责人和合规负责人共同签字确认。
3. 分层随机抽取 20 篇内容（包含职业、州、故事和数据页），任何关键事实均能在 3 分钟内定位到原始来源。
4. 随机抽取 8 个桌面/移动访问路径，无空页、死路、遮挡、横向溢出或广告误导。
5. 站点在没有 AFS、Related Search 和任何广告时仍具备完整用户价值。
